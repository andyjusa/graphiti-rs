## Reproduction and limits

Use a fresh labelled disposable database and explicit `COMPAT_TEST_DB_URL=redis://127.0.0.1:16379`. The test intentionally creates/deletes only its owned `project_staged_pipeline_20261002` graph. Run `cargo test --all-features --test compat staged_ingestion -- --ignored` with an optional `COMPAT_STAGED_REPORT` path to retain exclusively synthetic snapshots and mock responses. Copy that report and the checked-in SDK harness to the isolated image's writable `/tmp`, then invoke `python -S scripts/python-pi-pipeline.py` with a cleared environment and the explicit synthetic marker. The SDK harness uses only its fresh `project_python_pipeline_20261002` graph and refuses an existing populated graph. Do not invoke it in an operational container or attach original data/credentials.

Further cases remain necessary for larger/tied contexts, multiple interacting contradictions, unsupported custom models and fault recovery. The bounded substring fallback without fulltext indexes is not a general ranking-equivalence claim. Real provider quality/numerical comparisons, private original-memory restore, Pi resource measurements on restored data, external-writer coordination and authenticated gateway/cutover/rollback remain open. These synthetic tests do not complete the replacement objective.

The subsequent [private restore audit](restore-audit.md) found historical group exclusions and corrected the actual OpenAI SDK wire serialization. Its evidence is separate from the immutable 51-test staged-ingestion record.

## Deployed ten-type classification profile

An additional 2026-10-02 comparison uses the actual ten classification definitions copied privately from the observed deployment. Their names/descriptions stay outside Git; the profile SHA256 is `3eeb8a596599548cf0a61163c8f20fb10a0a73494664919d982f912b65c98ec8`. The isolated Python harness constructs each fieldless Pydantic model with the exact `type(name, (BaseModel,), {'__doc__': description})` factory in the observed MCP service. No operational entrypoint, credential or memory data is loaded.

Three synthetic episodes cover all ten classifications in message and text input, plus JSON that requests reversed classifications for existing names. Rust and the actual patched Python SDK produce identical canonical episode/node state after each input, with cumulative entity counts 10, 10 and 20. All three classification contexts and three unresolved-node classification/description contexts match independently, as do the actual Pydantic response schemas for eleven supplied model responses. Both implementations preserve existing entity UUIDs and labels when a later classification differs. Short names exercise model-assisted resolution; longer names also exercise deterministic resolution. This fixture deliberately produces no relationships; the earlier seven-episode record remains the selected generic-relationship evidence.

The ARM64 release fixture passes on Pi4 using the same observed image/module. Local validation passes 30 nonignored all-feature tests and ten isolated compatibility DB tests, with fmt and clippy warnings denied. To reproduce, run the ignored `configured_profile::ten_configured_classifications_message_json_text_and_existing_identity` test against an exclusively owned loopback DB on port 16379. The default profile contains ten synthetic definitions and is exercised by CI. Optionally set `COMPAT_PROFILE_TYPES_FILE` to a private ten-definition JSON array and `COMPAT_PROFILE_REPORT` to a new private report path; the report contains those labels/descriptions and must not be published. In a fresh isolated instance of the observed image, mount the report as `/tmp/profile-rust.json`, the profile as `/tmp/entity-types.json`, both Python helpers and the pinned edge patch. Invoke `python3 -S /tmp/python-pi-configured-profile.py` with a cleared environment, a valid container passwd entry, `GRAPHITI_PI_SYNTHETIC=graphiti-rs-compat-pi`, `GRAPHITI_TELEMETRY_ENABLED=false` and bytecode writes disabled. Network isolation and absent operational credentials are required. The Python graph must start empty. This establishes selected configured-classification storage parity with mock providers; default/invalid classification IDs, wider interacting relations, provider quality and operational adoption remain separate gates.
