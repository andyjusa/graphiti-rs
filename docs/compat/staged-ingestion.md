The Python run consumes the same 27 scripted responses produced by the Rust fixture; all actual Pydantic response schemas match the compiled schemas. After every episode, canonical node/fact/episode state matches, including labels, summaries, original creation times, temporal validity and supporting episode provenance. New random entity/fact UUIDs are mapped by their names/facts for cross-process comparison; reuse of the existing fact UUID is separately asserted within both implementations. Expiry is compared for presence because invalidation time is execution-specific. This is selected full ingestion evidence with fake model values, not general generation/embedding equivalence.

## Reproduction and limits

Use a fresh labelled disposable database and explicit `COMPAT_TEST_DB_URL=redis://127.0.0.1:16379`. The test intentionally creates/deletes only its owned `project_staged_pipeline_20261002` graph. Run `cargo test --all-features --test compat staged_ingestion -- --ignored` with an optional `COMPAT_STAGED_REPORT` path to retain exclusively synthetic snapshots and mock responses. Copy that report and the checked-in SDK harness to the isolated image's writable `/tmp`, then invoke `python -S scripts/python-pi-pipeline.py` with a cleared environment and the explicit synthetic marker. The SDK harness uses only its fresh `project_python_pipeline_20261002` graph and refuses an existing populated graph. Do not invoke it in an operational container or attach original data/credentials.

Further cases remain necessary for larger/tied contexts, multiple interacting contradictions, unsupported custom models and fault recovery. The bounded substring fallback without fulltext indexes is not a general ranking-equivalence claim. Real provider quality/numerical comparisons, private original-memory restore, Pi resource measurements on restored data, external-writer coordination and authenticated gateway/cutover/rollback remain open. These synthetic tests do not complete the replacement objective.
