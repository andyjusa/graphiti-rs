# Private original-memory restore audit

The replacement rehearsal uses a Redis RDB exported privately on the Raspberry Pi, the observed operational image and the exact FalkorDB module. The backup and original-memory report stay on the Pi with owner-private permissions; neither memory contents nor credentials belong in Git or CI. The original service continues running during the rehearsal. This initial snapshot does not replace the final queue-drained backup required for cutover.

`examples/compat-read-audit.rs` is a maintenance executable, separate from the MCP tools. It accepts an explicit private graph manifest and only loopback port 16380. Storage runs in read-only mode using GRAPH.RO_QUERY; 128-record keyset pages must account for every typed record. It validates UUIDs, timestamps, episode provenance, entity endpoint labels, and all present 3072-dimensional finite/nonzero native vectors. It returns counts and digests, without names, summaries, facts or episode contents. Each group has a 120-second deadline; missing/duplicate identities fail rather than yielding partial success. Groups outside the recorded MCP policy are reported separately and are not queried through this reader.

Some historical graphs contain records whose stored group differs from the physical graph. The maintenance audit explicitly counts these exclusions using their stored identity; this does not weaken any MCP guard. Direct MCP UUID lookups still reject a group mismatch. Search and related-fact candidates filter the record and endpoint groups before their limits, including the path without fulltext indexes. The original Python group-scoped wrappers also require the requested group to match the returned record.

Private comparison found 196 mis-scoped records across the restored database: 184 exact copies already exist in their intended groups, and 12 have differing properties. Every UUID has exactly one counterpart in its stored group. All copies are retained unchanged. Differences include creation time, summaries/classification fields and historical invalidation times; automatically changing group identities or replacing one copy with another would discard evidence. A report with scope exclusions is not a clean graph certification.

The synthetic regression reproduces foreign copies in a graph without indexes, verifies candidate exclusion and strict UUID lookup refusal, crosses the 128-row page boundary, and refuses a record missing its UUID. It creates/deletes only its dedicated disposable graph.

The actual OpenAI SDK 2.26.0 serializer was also exercised with the observed patched generation method and a mock HTTP transport. The checked-in synthetic [wire capture](../../tests/fixtures/observed-sdk-wire.json) shows that the SDK merges `extra_body` into the top-level request. Both Rust generation paths now send top-level `chat_template_kwargs`; tests compare the captured SDK fields and reject a literal `extra_body` wire field. This verifies serialization, without making paid provider calls.

Real provider behavior, original-memory MCP result comparisons, resource measurements, authenticated gateway rehearsal and operational cutover remain separate gates in [the replacement plan](replacement-plan.md).
