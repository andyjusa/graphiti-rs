# Modern OAuth header forwarding

The observed gateway0.1.2 omits `Mcp-Method` and `Mcp-Name`; the [earlier original-read rehearsal](original-read-results.md) recorded HTTP400/-32020 through that gateway while direct modern transport worked. The [official Streamable HTTP source](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/docs/specification/draft/basic/transports/streamable-http.mdx) defines mirrored routing headers for protocol2026-07-28. The actual locked Rust SDK3.5.0 additionally rejects repeated singleton routing headers.

The [reviewable patch](../../integration/oauth-gateway/standard-headers.patch) forwards both headers with all repeated values preserved. It leaves the original authentication, Origin check, fixed upstream bearer and other forwarding behavior unchanged. A first candidate using `HeaderMap.get` passed normal requests but collapsed duplicates: an adversarial request returned200 instead of400. The final patch uses `get_all` for these two headers, allowing the existing SDK guard to reject both identical and differing repeats. No header is synthesized from the body and no SDK guard is relaxed.

## Local and actual Pi evidence

On 2026-10-02, the input gateway's four source hashes were rechecked against the Pi host source. The helper tests temporary source copies against the actual Rust compatibility HTTP server and an owned empty local database. The unpatched baseline rejects all three selected modern requests with400/-32020. The patched gateway passes fifteen Rust tests, including eighteen HTTP cases: modern discovery/list/status, three legacy2025-11-25 requests, missing and mismatching principal headers, identical/differing duplicates of each principal header, missing/invalid/expired tokens and Origin refusal. The upstream receives all four duplicate requests intact and rejects them. Token/Origin refusals never reach the upstream; the fixed backend credential replaces the caller credential and unrelated headers remain absent. [Baseline](pi-oauth-headers-20261002/local-before.json), [patched run](pi-oauth-headers-20261002/local-after.json).

Release ARM64 binaries were compiled with the observed gateway lockfile and the current Rust runtime. On Pi4, the original gateway image and patched binary use separate newly seeded synthetic OAuth state and the same actual Rust backend on a fresh internal network, with the observed FalkorDB4.16.6/Redis8.2.3 image. Each gateway passes eighteen expected cases, thirty-six total. Both legacy tool lists and the patched modern tool list exactly match all ten recorded tool schemas. The disposable graph DB retains zero keys; OAuth state retains only the two seeded synthetic token hashes per variant, with no clients/codes/refresh grants. No GitHub login, original memory, real provider or operational routing is involved. [Pi report](pi-oauth-headers-20261002/pi-summary.json), [source/binary hashes](pi-oauth-headers-20261002/artifact-summary.json).

The four owned Pi containers and internal network, the owned local DB/network, and the synthetic OAuth credentials/state were removed after preserving private diagnostics. The original Graphiti, OAuth gateway and read-only restore keep their IDs/start times and remain running; original Graphiti and restore remain healthy. The original gateway source, initial backup hash and restoration audit hash are unchanged. [Preservation/cleanup](pi-oauth-headers-20261002/preservation-summary.json).

## Adoption limits

The patch is staged for review and remains unapplied to the operational gateway. Ordinary repository CI covers the Rust server; the independently sourced gateway validation is reproduced with the helper in [integration instructions](../../integration/oauth-gateway/README.md). This closes selected isolated header-forwarding evidence, not fresh GitHub OAuth login, active-client reconnect, original-memory reads through a switched service, operational rollback or adoption. The existing operational-switch/provider restrictions remain in force, and the full replacement goal is incomplete.
